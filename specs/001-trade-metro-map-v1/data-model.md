# Data Model: Trade Metro Map V1

**Date**: 2026-03-19
**Feature**: 001-trade-metro-map-v1

## Entities

### Station

Represents a city, port, or border crossing displayed on the map.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| id | string | yes | Unique slug (e.g., "laredo-nuevo-laredo") |
| nameEs | string | yes | Display name in Spanish |
| nameEn | string | yes | Display name in English |
| country | "MX" \| "US" \| "MX/US" | yes | Country. "MX/US" for combined border crossings |
| type | "city" \| "port" \| "border-crossing" | yes | Station type |
| tier | "mega" \| "major" \| "standard" | yes | Visual size tier (editorially assigned) |
| x | number | yes | Schematic X coordinate (grid units) |
| y | number | yes | Schematic Y coordinate (grid units) |
| tradeValueUsd | number \| null | no | Annual trade value in USD (border crossings) |
| tradeValueYear | number \| null | no | Year of trade value figure |
| truckCrossingsPerYear | number \| null | no | Annual truck crossings (border crossings) |
| containerVolumeTeu | number \| null | no | Annual container volume in TEU (ports) |
| primaryCommodities | string[] | no | Key commodity categories |
| corridorIds | string[] | yes | IDs of corridors passing through this station |
| sourceIds | string[] | yes | IDs of data sources backing this station's stats |

**Identity**: Unique by `id`. Border crossings use a combined ID
(e.g., "laredo-nuevo-laredo") per the clarification decision.

### Corridor

Represents a named trade route (metro line) on the map.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| id | string | yes | Unique slug (e.g., "linea-roja") |
| nameEs | string | yes | Spanish name (e.g., "Línea Roja") |
| nameEn | string | yes | English name (e.g., "NAFTA Spine") |
| color | string | yes | Hex color code |
| lineNumber | number | yes | Display order (1-9) |
| status | "active" \| "planned" | yes | Operational status |
| lineStyle | "solid" \| "dashed" | yes | Rendering style (dashed for planned) |
| lineWeight | "high" \| "medium" \| "low" | yes | Relative thickness tier |
| primaryMode | "truck" \| "rail" \| "both" | yes | Dominant freight mode |
| stationIds | string[] | yes | Ordered list of station IDs along route |
| totalTradeValue | string \| null | no | Narrative trade value (e.g., "$339B") |
| primaryCommodities | string[] | no | Key commodity categories |
| evidence | string | yes | Brief sourced evidence statement |
| sourceIds | string[] | yes | IDs of data sources backing this corridor |

**Identity**: Unique by `id`.

**Stations ordering**: `stationIds` defines the sequence in which
stations appear along the line. The renderer draws segments between
consecutive pairs.

### DataSource

Provenance reference for a cited dataset.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| id | string | yes | Unique slug (e.g., "bts-transborder-2025") |
| name | string | yes | Human-readable source name |
| authority | string | yes | Issuing organization |
| url | string \| null | no | URL (null for offline-only sources) |
| accessDate | string | yes | ISO date when data was accessed |
| dataYear | number | yes | Year the data covers |
| coverage | string | yes | What the source covers |

**Identity**: Unique by `id`.

### HeadlineStat

A key statistic displayed as a map annotation.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| id | string | yes | Unique slug |
| text | string | yes | Display text (e.g., "US-Mexico freight: $872.8B in 2025") |
| value | string | yes | The numeric value for emphasis |
| sourceId | string | yes | Reference to DataSource |

## Relationships

```text
Corridor ──has many──▶ Station (via stationIds, ordered)
Station ──belongs to many──▶ Corridor (via corridorIds)
Station ──cites many──▶ DataSource (via sourceIds)
Corridor ──cites many──▶ DataSource (via sourceIds)
HeadlineStat ──cites one──▶ DataSource (via sourceId)
```

## File Layout

```text
data/processed/
├── corridors.json    # Array of Corridor objects
├── stations.json     # Array of Station objects
├── sources.json      # Array of DataSource objects
├── headlines.json    # Array of HeadlineStat objects
└── data-dictionary.md  # Human-readable column descriptions
```

All files are generated by `data/scripts/transform.ts` from raw
inputs in `data/raw/`. The JSON schema in `contracts/` validates
these files at build time.
